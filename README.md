# SDF 2D → 3D Converter

Converts 2D SDF/MOL structures into 3D SDF with physically meaningful three-dimensional coordinates. All computation runs in the browser via WebAssembly; no server, no upload, and no data leaves the client.

Live: <https://sdf2d-to-3d.pages.dev>

## Method

Three-dimensional coordinates are generated by the **official RDKit C++ toolkit compiled to WebAssembly**, using the same algorithms as the Python `rdkit` package:

1. Parse the molfile (V2000 / V3000).
2. `MolOps::addHs` — add explicit hydrogens.
3. `DGeomHelpers::EmbedMolecule` with **ETKDGv3** (Experimental-Torsion Knowledge Distance Geometry; the default conformer-generation method in RDKit since 2018) to produce initial 3D coordinates.
4. `MMFF::MMFFOptimizeMolecule` (**MMFF94**) or, when MMFF parameters are unavailable, `UFF::UFFOptimizeMolecule` (**UFF**) for geometry refinement.

This is not a heuristic approximation or a custom geometry builder — it is RDKit itself.

## Build

The published `@rdkit/rdkit` (MinimalLib) build provides **2D coordinate generation only** and has no 3D embedding capability (no DistGeom or ForceField bindings). This project therefore compiles RDKit's `Code/MinimalLib` from source with added 3D bindings:

- `minilib.h` / `minilib.cpp` — add `JSMolBase::set_3d_coords(jsonParams)`, wrapping `EmbedMolecule` (ETKDGv3) and `MMFFOptimizeMolecule` / `UFFOptimizeMolecule`.
- `CMakeLists.txt` — link `DistGeomHelpers;ForceFieldHelpers;DistGeometry;ForceField;EigenSolvers` into the MinimalLib target.
- `jswrapper.cpp` — embind export of `set_3d_coords` / `set_3d_coords(jsonParams)`.

Emscripten build (Boost and zlib come from Emscripten ports; Eigen from the system):

```
emcmake cmake .. \
  -DRDK_BUILD_MINIMAL_LIB=ON -DRDK_BUILD_DESCRIPTORS3D=ON \
  -DRDK_BUILD_COORDGEN_SUPPORT=ON -DRDK_BUILD_INCHI_SUPPORT=OFF \
  -DRDK_USE_BOOST_SERIALIZATION=OFF -DRDK_USE_BOOST_IOSTREAMS=OFF \
  -DCMAKE_CXX_FLAGS="-O2 -DNDEBUG -sUSE_BOOST_HEADERS=1 -sUSE_ZLIB=1 -fwasm-exceptions" \
  -DCMAKE_EXE_LINKER_FLAGS="-fwasm-exceptions -sMODULARIZE=1 -sEXPORT_NAME=initRDKitModule -sALLOW_MEMORY_GROWTH=1"
```

`-fwasm-exceptions` is required: it lets invalid input (e.g. a valence error) raise a catchable exception instead of aborting the entire WebAssembly instance.

## Verification

Output validated independently with Python RDKit:

```
phenol     C6H6O     3D=True   ring angles 119.4–120.9°   max plane deviation 0.0000 Å
caffeine   C8H10N4O2 3D=True   both rings correct          max plane deviation 0.0000 Å
aspirin    C9H8O4    3D=True   ring angles ~120°           max plane deviation 0.0089 Å
```
